# 数据库设计文档

## 一、E-R 图（实体关系图）

系统共包含 10 个实体：patient（病人）、staff（医生/管理员）、department（科室）、schedule（排班）、tongue_record（舌苔检测记录）、medical_record（诊疗记录）、appointment（预约记录）、prescription（处方）、system_config（系统配置）、system_log（系统日志）。

### 实体关系一览

| 关系 | 基数 | 说明 |
| --- | --- | --- |
| department（科室）→ staff（医生/管理员） | 1 : N | 一个科室包含多名工作人员 |
| patient（病人）→ tongue_record（舌苔检测记录） | 1 : N | 一名患者可有多条舌苔检测记录 |
| patient（病人）→ medical_record（诊疗记录） | 1 : N | 一名患者可有多条诊疗记录 |
| patient（病人）→ appointment（预约记录） | 1 : N | 一名患者可有多条预约记录 |
| staff（医生/管理员）→ appointment（预约记录） | 1 : N | 一名医生可接诊多条预约记录 |
| staff（医生/管理员）→ medical_record（诊疗记录） | 1 : N | 一名医生可产生多条诊疗记录 |
| staff（医生/管理员）→ schedule（排班） | 1 : N | 一名医生可有多条排班记录 |
| schedule（排班）→ appointment（预约记录） | 1 : N | 一条排班对应多条预约记录 |
| department（科室）→ appointment（预约记录） | 1 : N | 一个科室可有多名患者的多条预约记录（依据 appointment.dept_id 外键推导；ER 图中未画出该连线） |
| medical_record（诊疗记录）→ prescription（处方） | 1 : N | 一条诊疗记录对应多条处方 |

## 三、关键业务规则实现

### 3.1 医生排班冲突检测

核心业务规则要求确保同一医生在同一日期的同一班次仅能存在一条有效排班记录，避免重复排班导致的资源冲突与业务逻辑混乱。

```sql
SELECT COUNT(*) FROM schedule
WHERE doctor_id = ? AND work_date = ? AND shift_type = ?;
```

**数据约束逻辑**：插入新记录前执行上述查询，若返回结果大于 0，判定为存在冲突，触发拦截机制禁止该条记录的插入操作。

### 3.2 预约号源动态控制

依据医生排班表中预设的最大接诊数，通过关联预约记录表，实时计算各时段剩余可预约号源，实现号源数量的动态管控与自动预警。

```sql
SELECT s.max_appointments - COUNT(a.appointment_id) AS remain
FROM schedule s LEFT JOIN appointment a ON s.schedule_id = a.schedule_id
WHERE s.schedule_id = ? GROUP BY s.schedule_id;
```

> 原图勘误：早期版本 SQL 中的 `s.max_appt`、`a.appt_id`、`s.id`（共三处）与 2.4/2.6 节表定义的字段名不一致（应为 `max_appointments`、`appointment_id`、`schedule_id`），原图疑似笔误，按本文表结构直接执行会报"未知列"。修正后如上。

**号源临界约束**：实时计算剩余号源(remain)，当数值小于等于 0 时，系统自动锁定该时段，拒绝接收新的预约请求，保障接诊能力匹配。

### 3.3 医生视角：当日预约与检测结果关联

医生登录系统后，可实时查看当日所有预约患者的完整列表，并自动关联每位患者最新的舌苔检测记录（含检测结果类型与舌苔图像），实现诊疗信息前置获取，提升问诊效率。

```sql
SELECT a.appointment_id, p.real_name, t.result_type,
t.image_url FROM appointment a JOIN patient p ON
a.patient_id = p.patient_id LEFT JOIN tongue_record t
ON t.patient_id = p.patient_id AND t.created_at =
(SELECT MAX(created_at) FROM tongue_record WHERE
patient_id = p.patient_id) WHERE a.doctor_id = ? AND
a.appointment_date = CURDATE();
```

### 3.4 患者视角：未过期预约待办提醒

患者登录后，首页将聚合展示所有未过期的有效预约记录，清晰呈现就诊科室、接诊医生及预约时间等关键信息，形成可视化的待办事项清单，避免错过诊疗时间。

```sql
SELECT a.appointment_id, d.dept_name, s.real_name,
a.appointment_date FROM appointment a JOIN department d
ON a.dept_id = d.dept_id JOIN staff s ON a.doctor_id =
s.staff_id WHERE a.patient_id = ? AND
a.appointment_date >= CURDATE() AND a.status = 1;
```

**核心价值**：通过多表关联查询与子查询优化，精准支撑医生与患者的双向业务视图，确保数据展示的实时性与准确性。
