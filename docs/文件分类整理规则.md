# 项目文件分类整理规则

> **用途**：新增任何文件/目录之前，先查本文档确定去处；本文档与 `.gitignore`、`README.md` 目录结构保持同步。
> 最近更新：2026-10-29

---

## 一、总原则

1. **git 仓库只放"交付物"**：自己写的源码、项目文档、小体积必要产物（.rknn / .pt）。
2. **三类东西一律不入库**（进 `.gitignore`，仅存本地）：
   - 内部管理文档：进度表、日报、项目手册 PDF
   - 第三方/课程参考资料：`references/` 整目录
   - 大文件与编译产物：超过 100MB 的文件（GitHub 硬限制）、数据集压缩包、ELF/可执行/build 目录
3. 单文件超过 50MB 提交前要警惕，**超过 100MB 禁止提交**。
4. 一类内容一个目录；文件名要能自解释，不允许"新建文件夹(2)"。

## 三、新文件速查表（核心）

拿到一个新文件，先看类型：

| 文件类型 | 去处 | 入库？ |
|---|---|---|
| 板端 C/C++ 源码（.cc/.h/.cpp） | `采集端代码/` | ✅ |
| 服务端 C/C++ 源码（未来） | `服务端/`（新建须登记） | ✅ |
| Qt 客户端工程 | `客户端/<端名>/` | ✅ |
| HTML 界面原型（`*原型*.html`） | `客户端/` | ❌ |
| .rknn 部署模型 | `models/` | ✅ |
| .pt 权重 / .py 训练脚本 / data.yaml | `training/` | ✅ |
| 数据集压缩包 / 超过 100MB 的大文件 | `training/` 或对应目录（仅本地） | ❌ |
| 设计文档 / 协议 / 决策清单（.md） | `docs/` | ✅ |
| SQL / 建库脚本 / 初始数据（.sql/.txt） | `docs/` | ✅ |
| 截图 / 演示配图 | `docs/images/` | ✅ |
| 第三方代码 / 课程资料 / 别人给的 demo | `references/<主题名>/` | ❌ |
| 厂商 SDK / 超大资料包 | `board-rv1106/` | ❌ |
| 编译产物：ELF、可执行、*.o、build/ | 留在编译目录，不提交 | ❌ |
| 进度表 / 日报 / 手册 PDF | 根目录（本地） | ❌ |
| Office 临时文件 `~$*` | 不管，已被忽略 | ❌ |

## 五、命名规范

- **文档/资料**：中文命名，一眼看懂（如 `RV1106串口通信协议说明.md`）
- **代码文件**：英文小写（`main.cc`、`tongue_def.h`）
- **日期**：统一 `YYYY-MM-DD` 或 `MM-DD`
- **版本**：`_v2`、`_v3` 递增；禁止"最终版""改""新"等模糊后缀
- **参考资料子目录**：按主题命名，里面保持资料原样，不重命名

## 六、查表没有的文件：三步判断法

1. **是谁的？** 自己写的 → 按端归目录（采集端 / 服务端 / 客户端）；别人给的 → `references/<主题>/` 或 `board-rv1106/`
2. **是文档吗？** 描述项目本身的 → `docs/`
3. **还定不了？** 先想能否并进现有目录；确实需要新建目录 → 在下方"目录变更登记表"加一行，并同步更新 `.gitignore` 与 `README.md` 目录结构
